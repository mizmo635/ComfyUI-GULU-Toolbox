# YSQ工具箱（ComfyUI-YSQ-Toolbox）

自用 ComfyUI 节点合集。只依赖 ComfyUI 自带环境（Pillow / numpy / torch），不需要安装任何额外依赖。

| 节点 | 分类 | 作用 |
|---|---|---|
| 🖼️ 图像后处理导出 | YSQ工具箱/导出 | 压缩（PNG / JPG）+ 贴透明底水印 + 保存到指定目录 |
| 📐 按边压缩 | YSQ工具箱/图像 | 按长边 / 短边等比压缩，可对齐倍数，输出压缩后的宽高 |
| 📂 图像批量循环导入 | YSQ工具箱/导入 | 逐张读图，每张把下游整条链路跑完，全部跑完自动结束 |

四个节点都**不在画布上显示预览**，需要看结果请接 ComfyUI 自带的预览节点，或直接看保存目录。

# 🖼️ 图像后处理导出

一个节点做完三件事：**压缩** → **加水印** → **保存到指定位置**。

输出端口：`处理后的图像` / `保存路径` / `分辨率信息`。

## ① 压缩：格式与压缩等级

| 参数 | 说明 |
|---|---|
| 保存格式 | `PNG`（无损）/ `JPG`（有损） |
| JPG质量 | 1~100，仅 JPG 生效。90~95 平衡，低于 70 有可见压缩痕迹 |
| PNG压缩等级 | 0~9，仅 PNG 生效。**无损**，只影响文件大小和保存耗时。0 最大最快，9 最小最慢 |
| PNG写入工作流 | 仅 PNG 生效。写入后图片拖回 ComfyUI 可还原整条工作流 |
| 最长边限制 | 等比缩小到不超过该像素，`0` = 保持原分辨率。顺带压体积用 |

实测同一张 7952×5304 的图：PNG lv0 = 126 MB，lv9 = 66 MB；JPG 质量 95 = 13.8 MB，75 = 4.9 MB，40 = 2.0 MB。

## ② 水印：透明底 PNG + 可调位置与边距

**准备水印图**：把透明底 PNG 放进

```
ComfyUI/input/watermarks/
```

然后 `水印来源` 选「水印文件」，下拉里就能选到（按修改时间倒序，最新的在最前面）。

> 列表是节点创建时读取的。新放了水印图之后，**刷新浏览器页面（F5）**，或者重新添加一个节点，才会看到新文件。

| 参数 | 说明 |
|---|---|
| 水印来源 | `关闭` / `水印文件` / `接入图像端口`（用上游生成的图） |
| 水印位置 | 九宫格 `左上 正上 右上 左中 正中 右中 左下 正下 右下` + `平铺` |
| 水印边距X | 距左 / 右边缘像素。`0` = 贴边 |
| 水印边距Y | 距上 / 下边缘像素。`0` = 贴边 |
| 水印宽度 | 占画面宽度的百分比（1~100），高度自动等比 —— 换分辨率也不会跑偏 |
| 不透明度 | 0~100，想低调给 60~80 |
| 旋转角度 | 0~359 度（逆时针），平铺时常配 30~45 度 |
| 水印间距 | 仅「平铺」生效，相邻水印之间的像素间隔 |

选「平铺」时两个边距自动隐藏。水印保留 PNG 的透明通道，不会出现白底方块。

## ③ 保存位置

| 保存位置 | 行为 |
|---|---|
| 输出目录（output） | 存到 ComfyUI 的 `output/` 下，用 `子文件夹` 指定相对路径（支持多级，如 `项目A/第一版`，留空 = 根目录） |
| 自定义绝对路径 | 存到硬盘任意位置，如 `G:/出图/成品`，目录不存在会自动创建 |

- 文件名 = `前缀_年月日时分秒.扩展名`，例如 `图像后处理_20261017195938.png`。后缀是 14 位纯数字时间，同一秒存多张时秒数自动顺延，**绝不覆盖已有文件**。
- `落盘开关` 选「不保存」时只把处理后的图像往下传，不写任何文件。

# 📐 按边压缩

按长边或短边等比压缩图片，可选对齐倍数，输出压缩后的图像和宽高。

| 输出端口 | 类型 | 说明 |
|---|---|---|
| 图像 | IMAGE | 压缩后的图像 |
| 宽度 | INT | 宽度（像素） |
| 高度 | INT | 高度（像素） |

## 参数

| 参数 | 说明 |
|---|---|
| 基准边 | `长边`：按较长那条边缩放（竖图按高度算）<br>`短边`：按较短那条边缩放 |
| 目标边长 | 希望基准边压到的像素值，默认 1024 |
| 对齐倍数 | 宽高各自**向下取整**到这个倍数，常用 8 / 16 / 32 / 64。填 0 或 1 = 不对齐 |
| 未缩放时尺寸 | 原图没超过目标边长时，`宽度/高度` 端口给什么值（三种都只改数值，图像不动）：<br>`输出实际尺寸` / `输出对齐后尺寸` / **`强制按目标边长计算`** |

## 节点上的尺寸面板

节点下方会直接显示计算后的宽高：

```
    1024 × 768
未缩放（原图 800×600） · 对齐 8
```

上面一行是最终输出的宽高，下面一行说明是「已缩放」还是「未缩放」、原图多大、对齐倍数多少。
执行一次就更新，不用去接文字节点看。

## 规则

1. **只缩不放**：选定的那条边 ≤ 目标边长 → 图片完全不缩放。
2. 需要缩放时：等比缩到该边 = 目标边长，然后再按对齐倍数向下取整（保证不会超过目标值）。
3. 未缩放时图像原封不动，只是尺寸端口可以按下面三种口径给值：
   - `输出实际尺寸` —— 原图多少就多少
   - `输出对齐后尺寸` —— 原图宽高各自向下对齐到倍数
   - `强制按目标边长计算` —— **不管原图多小，都按「目标边长 + 对齐倍数」算出宽高**
     （比如 800×600 → 1024×768，但图像仍是 800×600）。
     批量出图想先拿到"统一尺寸"的数值（写文件名、算比例、喂给下游）就用这个。

## 例子（对齐 8，目标 1024）

| 原图 | 基准边 | 结果 | 说明 |
|---|---|---|---|
| 7952×5304 | 长边 | 1024×680 | 等比缩到长边 1024，再各自向下对齐 8 |
| 1024×1024 | 长边 | 1024×1024（不缩放） | 没超过目标 |
| 800×1200 | 短边 | 800×1200（不缩放） | 短边 800 ≤ 1024 |
| 800×1200 | 长边 | 680×1024 | 按长边压缩，683 向下对齐成 680 |
| 1000×750 | 长边 | 1000×750（不缩放） | 选「输出对齐后尺寸」→ 端口给 1000×744；选「强制按目标边长计算」→ 端口给 1024×768；图像都仍是 1000×750 |

> 最后一行就是「不压缩、但要对齐后的宽高」的用法：图像不动，尺寸端口给对齐值。

# 📂 图像批量顺序导入

**一轮工作流只读一张图，跑完自动推进到下一张，全部跑完自动停止。**

接哪个输出端口，就自动走哪种模式，不用额外设开关：

| 你接的端口 | 模式 | 行为 |
|---|---|---|
| **图像** | 顺序模式 | 一轮读一张，跑完自动下一张，全程低占用（内存里只有当前这张） |
| **全部图像** | 一次模式 | 把整个目录读成一个 batch 一次性输出，**不循环**（适合喂批处理节点） |

## 它是怎么顺序跑的

```
第 1 轮：读 p01 → 整条工作流跑一遍 → 结束
        ↓ 节点自动把「循环位置」+1 并重新提交
第 2 轮：读 p02 → 整条工作流跑一遍 → 结束
        ↓ ...
第 5 轮：读 p05 → 跑完，没有下一张 → 停止，循环位置复位为 0
```

每一张都是**独立的一轮完整执行**：有自己的进度条，随时可以点取消。

## 它怎么知道「这一轮跑完了」

判断依据不是「导入节点自己跑完了」（那时下游可能还在采样），而是框架广播的
**`execution_success`（整轮工作流全部结束）**：

| 事件 | 含义 | 用途 |
|---|---|---|
| `executed` | 某个节点跑完了 | 太早，只用来记下「这轮还有下一张」 |
| **`execution_success`** | **整轮工作流全部跑完** | ✅ 收到它才推进下一张 |
| `execution_error` / `execution_interrupted` | 出错 / 你点了取消 | 停止推进 |

所以工作流不管多复杂（多级串联、多分支、多个输出节点），都**一定等全部跑完**才取下一张。

> ComfyUI 的图是 DAG，线不能接回自己形成环（会被 `dependency_cycle` 拒绝），
> 所以这个信号来自框架事件，不需要连输入端口或 For循环 / WhileLoop 节点。

## 节点上的预览

输入端口下方显示当前这张图，图的正下方是：

```
    400 × 300
s05.jpg  ·  第 5/5 张
```

第一行分辨率，第二行文件名 + 进度（一次模式下显示「共 N 张」）。
点图片可以开新标签看大图。

## 参数

| 参数 | 说明 |
|---|---|
| 图片目录 | 要导入的文件夹，可直接粘资源管理器路径 |
| 包含子文件夹 | 打开后连子目录一起扫 |
| 图片扩展名 | 逗号分隔白名单，默认 11 种：`png, jpg, jpeg, webp, bmp, gif, tif, tiff, jfif, ppm, pgm` |
| 排序方式 | 文件名升序 / 降序、修改时间升序 / 降序 |
| 起始索引 | 从第几张开始（0 = 第一张），中断后从这里续跑 |
| 加载数量 | 这一批最多处理几张，0 = 全部 |
| 循环位置 | 自动推进用，会看到它 0→1→2…跳，不用手填 |

## 典型接法

```
📂 图像批量顺序导入 ──图像──→ （采样 / 处理链）→ 🖼️ 图像后处理导出
```

一次模式（不走循环）：

```
📂 图像批量顺序导入 ──全部图像──→ （批处理节点）
```

## 注意

- **顺序模式运行时保持浏览器页面开着**：循环靠页面推动，关掉页面就停在这一张。
- 想中途停：直接点「取消」。
- 想跳过几张：把 `起始索引` 改大。
- 每次手动点「运行」都会从 `起始索引` 重新开始（循环位置自动归零）。
- 一次模式要求**目录里图片尺寸一致**，不一致会直接报错并提示先用「📐 按边压缩」统一；
  顺序模式没有这个限制。
- 每轮下游用的是同一份参数，**采样器 seed 不会自动变**。需要每张不同的话，
  在采样器前接 seed 递增 / 随机节点。
- 目录很大时先用 `加载数量 = 2` 试链路。

# 🔁 LoRA 轮转

**登记一组人物 LoRA，点一次运行，用同一套提示词 / 同一种子，逐个 LoRA 各出一张。**

```
第 1 轮：LoRA 甲（1.10）→ 整条工作流跑一遍 → 存图
        ↓ 自动推进
第 2 轮：LoRA 乙（1.05）→ 整条工作流跑一遍 → 存图
        ↓ ...
出图数量 = 清单里「开关打开」的 LoRA 数量
```

## 怎么登记 LoRA

节点上有一块面板，操作全在面板里：

```
[ 选择要添加的 LoRA（535 个） ▼ ]  [ + 添加 ]  [ 批量 ]
☑ Krea2_自建人物/角色甲.safetensors   ◀ 1.10 ▶  ×
☑ Krea2_自建人物/角色乙.safetensors   ◀ 1.05 ▶  ×
☐ Krea2_自建人物/角色丙.safetensors   ◀ 0.80 ▶  ×
```

- **下拉选择 + 添加**：下拉里是 loras 目录下全部 LoRA（含子目录），键盘输入可快速过滤
- **☑ 开关**：关掉的 LoRA 不参与轮转（灰色的那行会被跳过）
- **◀ ▶**：每次 ±0.05 调强度；新添加的行用「默认强度」的当前值
- **×**：从清单里移除

### 批量添加

点 **批量** 展开一个搜索 + 多选区域：

```
[ 搜索：输入路径关键词过滤（如 Krea2_自建人物） ]
☑ 角色甲.safetensors
☑ 角色乙.safetensors
☐ 角色丙.safetensors
[ 添加选中 12 个 ]  [ 全选匹配 ]        匹配 12
```

- 搜索框按**路径关键词**过滤（子目录名也行，比如输 `Krea2_自建人物` 就只剩这个目录的）
- 勾选要的，或直接点 **全选匹配** 把当前搜索结果一次性全选
- 点 **添加选中 N 个** 批量加进清单（已存在的会自动跳过）
- 一次最多显示前 150 条，超出会有提示，缩小搜索范围即可

批量加完自动关闭批量区；新加的 LoRA 都用「默认强度」

清单存在节点的 `LoRA清单` 参数里（JSON），面板会自动维护，不用手改。

## 参数

| 参数 | 说明 |
|---|---|
| model | 基础模型（接 Checkpoint / UNet 加载器的 MODEL 输出） |
| 默认强度 | 新添加 LoRA 时的初始强度 |

## 输出

| 端口 | 类型 | 说明 |
|---|---|---|
| 模型 | MODEL | 已应用当前 LoRA 的模型 |
| 当前LoRA | STRING | 当前 LoRA 的完整名字（可以接字符串拼接写进文件名） |

节点下方显示进度：`2 / 4` 和 `Krea2_LLH_1.safetensors · 强度 1.05`。

## 典型接法

```
Checkpoint 加载器 ─MODEL─→ 🔁 LoRA 轮转 ─MODEL─→ KSampler → 🖼️ 图像后处理导出
Checkpoint 加载器 ─CLIP─────→ CLIP文本编码（直接接，不经过本节点）
```

> 本节点**只改扩散模型**，不碰 CLIP / text encoder —— 等价官方的 LoRA Model Only。
> 人物 LoRA 绝大多数只训了 UNet，本来就没有 text encoder 权重可应用，所以这样最干净。

**种子固定**：只要 KSampler 的 seed 设成 `fixed`，每一轮用的就是同一个种子，
配合同一套提示词 → 出来的就是「同姿势同构图，不同人物」。

## 注意

- 每次手动点「运行」都从清单第一个（开关打开的）开始。
- 运行时要保持浏览器页面开着（和批量导入一样靠页面推进）。
- LoRA 文件有缓存（最多 12 个），同一批里不会反复重读。
- 清单里的 LoRA 在磁盘上被删了的话，那一轮会报错停下，看控制台能知道是哪一个。

## 常见问题

**节点列表里找不到？**
重启 ComfyUI，或浏览器强制刷新（Ctrl+F5）。

**水印下拉里没有我刚放的图？**
刷新页面。列表在节点创建时读取。

**水印贴上去是白底方块？**
这张图没有透明通道。请导出带 alpha 的 PNG（PS：存为 Web 格式，勾选透明度）。

**PNG 写入工作流后图片变大？**
正常，工作流 JSON 占几十 KB。不想保留就选「不写入」。

**保存到自定义路径后在 ComfyUI 里看不到？**
「打开输出目录」只指向 output。自定义路径请用资源管理器打开。

**按边压缩输出尺寸和图片实际尺寸对不上？**
只会在「未缩放 + 输出对齐后尺寸」这一种组合下出现，是刻意设计：图不动，只给对齐后的数值。

**批量导入跑了几张就停了？**
看控制台日志的 `批量导入 x/N`，卡在哪张就是那张图有问题（损坏 / 格式不支持）。修好或删掉再跑，
用「起始索引」从断点续跑。
